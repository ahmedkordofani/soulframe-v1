# SoulFrame V6.0.8 - Local Owner Access

## Purpose

Introduce an explicit local access boundary for the Node development API while preserving the existing schema and browser-only workflows. **This is not production authentication.**

## How to use

1. Stop the previous API process.
2. Start `npm run dev:api` in a terminal. A new random local-owner token appears in that terminal. Keep it private.
3. Start `npm run dev` in a second terminal.
4. Open Product > Output > Saved Projects. Paste the token into **Unlock local project storage**.
5. Save, list, load, overwrite, restore and export projects as normal.
6. Select **Lock projects** to clear the secret from tab memory, or refresh the page.

Restarting the API invalidates the previous token. Re-enter the new token from the current backend terminal.

## What is protected

All project, recovery, backup export and backup import HTTP endpoints require the bearer token on the normal CLI server. The health check remains public but never exposes the secret. Loopback, Origin, Fetch Metadata, request-size, security-header and rate-limit protections remain in place.

## What this is not

- No username/password accounts, roles, sessions or login provider.
- No secure multi-user cloud hosting; the JSON store remains local and unencrypted.
- Browser JavaScript in the same origin can access tab-memory values; this is **not** protection from XSS.
- Other local programs running as the same user might read the terminal or inspect process memory.
- Locking a tab clears the client-side token; it does not revoke the token from the running server. Restart the API to rotate it.
- No audio upload, automatic backup, account recovery or hosted report URLs.

## Developer and test API

`createSoulFrameApiServer({ authToken })` enables a token gate; tokens must be 43-character base64url secrets generated by `generateLocalAccessToken()`. The generic `createSoulFrameApiServer()` factory is token-protected by default. Embedded test fixtures may deliberately opt out with `authToken: null` **only for tests**; this is insecure for real use. The normal CLI entry point generates and prints a new token.

## Test checklist

1. `npm run verify` runs the Node regression suite and the Vite production build.
2. Confirm the backend prints a new token and the frontend shows an Unlock form.
3. Confirm project requests return HTTP 401 without the token and with an incorrect token.
4. Enter the correct token and confirm Save, Load, backup Export/Import and Recovery work with demo metadata.
5. Lock the tab and confirm project operations become unavailable.
6. Restart the API, confirm the old token fails and the new token unlocks the UI.
7. Confirm browser-saved projects still work with the API offline.

The V6.0.8 change does not modify the storage schema or existing project records.
